🔴 Critical Issues

C1 — Plaintext Secrets in Kubernetes secrets.yaml
k8s/secrets.yaml contains default JWT_SECRET (terzocloud_jwt_secret_2025_change_me_in_prod) and ENCRYPT_KEY in plain stringData. If this file is committed to version control or shared, it exposes the cryptographic root of the application. Anyone with these keys can forge JWTs and decrypt stored secrets (SMTP passwords, OAuth tokens).
Securityk8s/secrets.yamlCRITICAL
C2 — CORS_ORIGINS Set to Wildcard “*” in K8s ConfigMap
k8s/configmap.yaml sets CORS_ORIGINS: "*". The server correctly restricts CORS when this value is a real origin list, but a wildcard bypasses all protection. Combined with SameSite=lax cookies, this significantly weakens cross-origin request forgery defenses in the K8s environment.
Securityk8s/configmap.yamlCRITICAL
C3 — Kubernetes Ingress Has No TLS / HTTPS Configuration
k8s/ingress.yaml defines only HTTP rules with no tls: block and no HTTP-to-HTTPS redirect annotation. All portal traffic — including JWT cookies and admin credentials — travels in cleartext.
Securityk8s/ingress.yamlCRITICAL

🟠 High-Priority Issues

H1 — OAuth SSO Token Exposed in Redirect URL
In routes/auth.routes.js (Google callback), after successful OAuth the JWT is appended as a query parameter: res.redirect(`/login?sso_token=...`). Tokens in URLs are stored in browser history, server access logs, and any CDN or proxy — leaking valid session tokens outside the HttpOnly cookie.
Securityauth.routes.jsHIGH
H2 — Rate Limiting Missing on Most Admin Endpoints
Rate limiting is applied only to POST /api/auth/login and one support approval route. Admin endpoints such as POST /api/admin/users (create admin accounts) and PUT /api/users/:id/app-access are unprotected, leaving them open to brute-force enumeration or bulk abuse.
Securityroutes/admin/HIGH
H3 — No Dedicated Health-Check Endpoint — Probes Use CSRF Token Route
K8s readiness and liveness probes both target /api/csrf-token. This creates cookies on every probe hit, mixes health semantics with auth concerns, and adds unnecessary overhead. A dedicated /health endpoint returning a simple 200 OK is the correct pattern.
DevOpsk8s/app.yamlHIGH
H4 — ‘unsafe-inline’ in Content Security Policy Nullifies XSS Protection
server.js configures Helmet CSP with scriptSrc: ["'unsafe-inline'"] and scriptSrcAttr: ["'unsafe-inline'"] to support inline onclick/onsubmit handlers spread across all HTML pages. This effectively disables one of the most effective browser-side XSS mitigations.
Securityserver.jsHIGH

🟡 Medium Issues

M1 — Duplicate Route Registration (/api and /api/v1) with Redirect Anti-pattern
mountApiRoutes() is called twice, doubling every route handler in memory. The /api/v1/sheet-sync/run endpoint just 307-redirects to the /api equivalent — this is misleading and breaks the versioning promise.
Architectureserver.jsMEDIUM
M2 — No Input Validation Library — Manual Field Whitelisting Only
Routes whitelist field names but do not validate types, lengths, or formats. Email format is validated only by Mongoose’s regex. A schema validation library (Zod, Joi, express-validator) at the route boundary would produce consistent errors and eliminate an entire class of type-coercion bugs.
Robustnessroutes/MEDIUM
M3 — Business Logic and One-time Migrations Embedded in server.js
The ~60-line /api/sheet-sync/run handler and the location migration endpoint (/api/migrate-location) live directly in server.js. The migration has no guard against re-running and should be a one-time offline script, not a live API route.
Architectureserver.jsMEDIUM
M4 — Admin Password Minimum Length Is Only 6 Characters
AdminUser.js enforces a minimum password length of 6. For admin accounts that control integrations, SCIM tokens, and all employee data, 12+ characters (or a passphrase policy) is the recommended minimum.

🟢 Strengths & Well-Implemented Patterns

✅ Secrets Encrypted at Rest in Database
OAuth client secrets, SMTP passwords, and API tokens are encrypted with AES-256-CBC (utils/secret-crypto.js) before storage and decrypted on demand — excellent practice for third-party credential protection.
✅ Solid CSRF Double-Submit Cookie Implementation
CSRF protection via _csrf cookie + X-CSRF-Token header is correctly bypassed only for login, logout, and SCIM (Bearer auth). All other state-changing requests are validated.
✅ JWT Issued as HttpOnly, Secure Cookie
Login sets the JWT in an HttpOnly, SameSite=lax, Secure-in-production cookie, preventing JavaScript from reading the token and providing strong XSS mitigation.
✅ Google OAuth2 CSRF State Validation with Expiry
The OAuth flow stores a random state in an HttpOnly cookie, validates it on callback with a 10-minute expiry check, and immediately clears it (one-time use) — a textbook implementation.
✅ Graceful Shutdown and Process Safety Nets
SIGTERM/SIGINT handlers drain in-flight requests, clear intervals, and close MongoDB cleanly. uncaughtException and unhandledRejection handlers prevent silent failures in production.
✅ Mass Assignment Prevention via Field Whitelists
Every write route explicitly whitelists allowed fields before passing to Mongoose, preventing prototype pollution or unintended field injection across all entity types.
✅ DB-Driven RBAC with Fine-Grained Permissions
role-permission.service.js resolves permissions dynamically from the database, allowing permission changes without a code deploy. Super-admin operations have a hard-coded role guard as a backstop.
✅ Docker Compose with MongoDB Health Check
docker-compose.yml uses a proper mongosh ping healthcheck with depends_on: condition: service_healthy, ensuring the app never starts before the database is ready.
✅ Zero-Config Dev via In-Memory MongoDB Fallback
When no MONGO_URI is set, the server auto-starts a mongodb-memory-server instance — lowering the barrier for new contributors who don't have a local MongoDB install.

💡 Prioritized Recommendations

1. Rotate and Seal K8s Secrets (C1): Replace plaintext stringData with properly generated secrets via kubectl create secret generic using openssl rand -hex 32 values. Never commit the file with real credentials. Consider Sealed Secrets or a vault solution for long-term management.
2. Fix CORS in K8s ConfigMap (C2): Change CORS_ORIGINS: "*" to your actual production domain, e.g. CORS_ORIGINS: "https://portal.terzocloud.com". One-line change, high security impact.
3. Add TLS to Ingress (C3): Add a tls: block to ingress.yaml with a cert-manager annotation (e.g. cert-manager.io/cluster-issuer: letsencrypt-prod) and the annotation nginx.ingress.kubernetes.io/ssl-redirect: "true".
4. Remove JWT from the OAuth Redirect URL (H1): After Google callback, set only the HttpOnly cookie and redirect to /admin directly. The frontend can call GET /api/auth/me to confirm the session. Remove the ?sso_token= parameter entirely.
5. Add a Dedicated /health Endpoint (H3): Add app.get('/health', (req, res) => res.json({ ok: true, uptime: process.uptime() })) and update all K8s probes to target it. This is a safe, stateless route suitable for high-frequency checks.
6. Move Inline Handlers to External JS Files (H4): Migrating onclick/onsubmit logic out of all HTML files allows removing 'unsafe-inline' from the CSP, re-enabling effective browser-side XSS protection.
7. Delete server.js.bak and Add *.bak to .gitignore (M5): Run git rm server.js.bak. Review the file first for any credentials that may need rotating.
8. Raise Admin Password Minimum to 12 Characters (M4): Update minlength in AdminUser.js from 6 to 12 and document a passphrase recommendation in the admin onboarding guide.
9. Extract Inline Logic from server.js (M3): Move the /api/sheet-sync/run handler into sheet-sync.routes.js. Convert /api/migrate-location into a standalone offline script (scripts/migrate-location.js) and delete it after the migration is confirmed complete.
10. Introduce a Schema Validation Library (M2): Add Zod or Joi schemas for at minimum user creation, asset creation, and admin user creation routes. This consolidates validation logic, produces consistent error messages, and catches type mismatches before they reach the database layer.
